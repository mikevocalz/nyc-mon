# R2 cell hosting: publish, verify, rollback

The app streams Valdrada's cells from Cloudflare R2. Every byte a client can fetch is pinned by
`packages/app/features/game/world/cell-source/data/vd-cells-manifest.ts` (sha256 + byteLength, generated by
`tooling/city/vd-port/write-cells-manifest.mjs`). These tools move that pinned set between disk and the bucket.

## Layout

```
releases/<release-id>/<path>        one object per manifest cell; immutable, x-amz-meta-sha256 pinned
releases/<release-id>/manifest.json the release's pin list + ODbL block; always uploaded LAST
releases/current                    activation pointer (JSON {"release": "<id>"}); the public edge resolves
                                    releases/current/<path> from it
```

`<path>` is the manifest's `path` field — exactly what `cell-source.ts` fetches as `${baseUrl}/${path}`, so
`R2_PUBLIC_BASE_URL` for the app ends at `releases/current/`.

## Setup

```
cp .env.r2.example .env.r2   # fill in; never commit. .env* is gitignored.
export $(grep -v '^#' .env.r2 | xargs)   # or use your shell's dotenv
```

`R2_ACCOUNT_ID`, `R2_BUCKET_NAME`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` are required by
`r2-publish.mjs`. `R2_ENDPOINT` overrides the S3 endpoint (default `https://<account>.r2.cloudflarestorage.com`,
path-style). `r2-verify.mjs` needs only `R2_PUBLIC_BASE_URL`.

## Publish

```
node tooling/city/r2-publish.mjs --dry-run            # local pin check + plan; no network
node tooling/city/r2-publish.mjs                      # release r<yyyymmdd UTC>-<manifest sha8>
node tooling/city/r2-publish.mjs --release r20261030-0123abcd --concurrency 8
```

Order inside a publish: re-hash every baked file against the manifest (fails closed on drift) → HEAD-skip
unchanged objects (Content-Length + stored `x-amz-meta-sha256`) → PUT missing/changed cells with
`Cache-Control: public, max-age=31536000, immutable` and `application/octet-stream` → PUT
`releases/<id>/manifest.json` LAST → PUT `releases/current` (skip with `--no-activate`). Uploads run 8-wide
with retry/backoff on 429/5xx and are resumable via `tooling/city/.cache/r2-publish-state.json` — rerun the
same release to continue an interrupted publish.

## Verify

```
node tooling/city/r2-publish.mjs --verify --release r20261030-0123abcd   # S3 GET + re-hash vs pins
R2_PUBLIC_BASE_URL=https://city-assets.nyc-mon.city/releases/current/ \
  node tooling/city/r2-verify.mjs                                       # public URL: HEAD+GET, Cache-Control, CORS, Range
```

`r2-verify.mjs` exits non-zero on any FAIL and needs no credentials — it exercises exactly the URL the app hits.
Staging check: the `r2.dev` public endpoint serves object paths literally (nothing resolves the `releases/current`
pointer), so aim the base at the release prefix —
`R2_PUBLIC_BASE_URL=https://pub-8272e2d358874d0580d90a49b1bede7d.r2.dev/releases/<release-id>/`.

## Rollback

```
node tooling/city/r2-publish.mjs --rollback r20261030-0123abcd
```

Writes only the `releases/current` pointer — nothing is deleted, old releases stay intact and immutable.
The target must already have its `manifest.json` (the tool HEADs it and refuses otherwise). Release objects are
never deleted; retire old releases by bucket lifecycle policy if storage matters, not by hand.

## Rotate credentials

The publish token is a Cloudflare R2 API token scoped object read+write to the bucket. To rotate: create the
replacement token in the Cloudflare dashboard, update the local `.env.r2` and the `R2_ACCESS_KEY_ID` /
`R2_SECRET_ACCESS_KEY` GitHub secrets, run `--dry-run` + a small `--verify` to confirm the new pair, then delete
the old token. Tokens are env-only and are never printed — the tools read them from the environment and name
missing variables, never their values.

## Recovery

- **Interrupted publish:** rerun the same command. The state file in `tooling/city/.cache/` skips objects already
  confirmed; HEAD-skip makes a fresh run idempotent anyway.
- **Bad release went live:** `--rollback <previous-good-id>`; clients re-resolve `releases/current` within the
  pointer's cache window (`Cache-Control: no-cache`).
- **Corrupt object detected by `--verify`:** re-run the publish for that release — the HEAD check re-PUTs any
  object whose stored sha256 does not match the pin.
- **Lost local bake:** restore `tooling/city/.cache/vd-lod16` from a workstation copy or rebuild via
  `tooling/city/vd-port/bake-far.mjs` + `write-far.mjs` + `write-cells-manifest.mjs`, then publish.

## CI

`.github/workflows/vd-cells-publish.yml` is dispatch-only for the real publish (`environment: production`):
dry-run → publish → S3 verify → public verify. Its PR leg runs manifest validation plus the cell-source
`node --test` suite with no credentials. The far tier's bytes are gitignored (ODbL data is not committed), so a CI
publish restores `tooling/city/.cache/vd-lod16` from the actions cache keyed `vd-lod16-<manifest-sha8>`; on a cache
miss or a stale restore the dry-run's pin check fails closed. Seed the cache from a maintainer workstation or run
the publish locally.

## ODbL 1.0 §4.4

The cells are a derivative database of OpenStreetMap data. `releases/<id>/manifest.json` carries the full pin
list plus the attribution block (credit "© OpenStreetMap contributors, ODbL 1.0" and the license link) — that
manifest object together with the cells it pins **is** the derivative-database offer ODbL §4.4 requires. Keep the
pins in the served payloads so the license stays attached to the data; see
`packages/app/features/game/world/cell-source/ATTRIBUTION.md`.

## Secret safety

Credentials arrive only through the environment (`R2_*`), are never written to state files, logs, or the bucket,
and never appear in URLs. Do not put tokens in the manifest, the workflow YAML, or `R2.md`. The example file
`.env.r2.example` documents the variables with empty values; `.env.r2` and every `.env.*` stay gitignored.
