# 0017 — The web simulator is its own package, and Claude runs on Bedrock's Messages endpoint

- **Status:** Accepted
- **Date:** 2026-10-08
- **Deciders:** the lead (lane D, Alexa+ hackathon); recorded for Mike
- **Sources:** ADR 0009, ADR 0015, `docs/alexa/HACKATHON.md`, `docs/alexa/PLATFORM-DOCS.md` §2.7 and §3.5, MCP Apps spec 2026-01-26 ("Sandbox proxy", "Content Security Policy Enforcement"), https://platform.claude.com/docs/en/build-with-claude/claude-in-amazon-bedrock and https://platform.claude.com/docs/en/build-with-claude/claude-on-amazon-bedrock-legacy (both read 2026-10-08)
- **Code:** `packages/web-sim`; run guide `docs/alexa/SIMULATOR.md`

## Context

Judges see the Alexa+ entry through our own simulator (ADR 0015). It has to be a real MCP client, render MCP Apps views, run Claude on Amazon Bedrock with AWS credentials kept off the browser, and run on a judge's laptop from the repo. Hosting is optional (FAQ: "A locally runnable public repo plus your demo video is enough").

The MCP Apps spec says a web host "MUST wrap the View ... through an intermediate Sandbox proxy" and "The Host and the Sandbox MUST have different origins." That second origin decides where the simulator can live.

The lane brief asked for the Bedrock Converse API with a current Claude model. Anthropic's Bedrock docs split two integrations. The legacy one ("`InvokeModel` and `Converse` APIs with ARN-versioned model identifiers") is titled "Opus 4.6 and earlier". Its model table leaves out Opus 5.5, Sonnet 5.5 and the other current models, which "are reachable through `InvokeModel` on `bedrock-runtime`" and are "served by the same infrastructure as the Claude in Amazon Bedrock endpoint". Neither page lists Converse for Opus 5.5. The current integration is the Messages API at `https://bedrock-mantle.{region}.api.aws/anthropic/v1/messages`, model id `anthropic.claude-opus-5-5`.

## Decision

1. **New package `packages/web-sim`, not a route in `apps/web`.** It is a Vite + React page with a small `node:http` server. The server runs two listeners: the page and `/api` on one origin (default `:5180`), and the sandbox proxy on a second (default `:5181`). A Next.js route would need a second deployment or domain for the proxy and a Next build for every simulator change, and it would put Bedrock code next to the product site. The product site stays untouched.
2. **The browser is the MCP client.** It sends `initialize`, `tools/list`, `tools/call` and `resources/read` over Streamable HTTP with `@modelcontextprotocol/client` 2.3.1, straight to the MCP server. This is the FAQ's "web page that acts as an actual MCP client". The agent loop (`src/shared/agentLoop.ts`) also runs in the browser.
3. **One server route holds the model.** `POST /api/model` runs one model turn. The server owns the system prompt (the Agent Skill file plus a short host note), the model id, `max_tokens` and effort. The browser sends only the conversation and the tool list it got from the MCP server. The route checks Origin, rate-limits per address, validates the body, and streams server-sent events back.
4. **Claude on Amazon Bedrock through the Messages endpoint.** The route uses `AnthropicBedrockMantle` from `@anthropic-ai/bedrock-sdk` 0.34.3 with the default AWS credential chain. The default model id is `anthropic.claude-opus-5-5` (`SIM_BEDROCK_MODEL_ID` overrides it), effort defaults to `low` for speakable replies, and the skill is cached with an explicit `cache_control` breakpoint. This replaces the Converse API in the brief: Converse is documented only for the legacy ARN-versioned models. The IAM action is `bedrock-mantle:CreateInference`. It is still Amazon Bedrock, so the AWS Builder entry stands.
5. **MCP Apps hosting follows the spec's web-host shape.** The page reads the `ui://` resource, loads `/sandbox?csp=<json>` from the second origin in an iframe, and connects an `AppBridge` (`@modelcontextprotocol/ext-apps` 2.0.3) over `postMessage`. The proxy writes the view into an inner iframe. The view's `_meta.ui.csp` goes out as an HTTP `Content-Security-Policy` header on the proxy document, which the view cannot loosen, with `frame-ancestors` pinned to the simulator origin. With nothing declared, the view gets `connect-src 'none'`. Views may call app-visible tools only; the dev presence hook and model-only tools are refused at the bridge.
6. **Sign-in is OAuth 2.1 authorization code + PKCE as the public client `nyc-mon-sim`.** Discovery runs from the MCP server's RFC 9728 metadata to lane B's authorization server. The simulator requests the PRM scopes minus `mcp:service`, which is the client-credentials scope. Tokens live in sessionStorage. `SIM_AUTH_MODE=dev-bypass` skips sign-in; it is an explicit flag and pairs with the MCP server's `OAUTH_DEV_BYPASS=1`.
7. **The page is built from the kit.** It renders through the same Vite pipeline as Storybook (react-native-web aliases, worklets and TypeGPU transforms, optimizer list), moved out of `apps/storybook/.storybook/main.ts` into `packages/config/vite/kit-web.mjs` so both apps share one copy, plus Tailwind v4 over `@acme/theme/theme.css` as in Storybook's `globals.css`. The device is a page-surface `SolidPanel`; the reply and empty states are notch `Card`s used as `MonsIndexPage` uses them; every control is the kit `Button`; the composer is `Form` + `TextField`; status is `Badge`; notices are `Banner`; the header carries `BrandWordmark`. Push-to-talk needed press-and-hold, so `Button` gained `onPressIn`, `onPressOut` and `aria-pressed` in `packages/ui` (story `UI/Button/Hold To Talk`). The only element the kit has no primitive for is the MCP Apps iframe, wrapped in `ViewFrame` (`src/client/ViewFrame.tsx`) with kit token classes and no styling of its own. MCP Apps views draw their own kit cards; the host doesn't restyle them.

## Consequences

- Judges run one command; the page and sandbox ports must both be free. The MCP server must list the simulator origin in `MCP_ALLOWED_ORIGINS`.
- `/api/model` answers any same-origin caller, and a non-browser client can forge `Origin`. The per-address rate limit (`SIM_RATE_LIMIT_PER_MIN`) and `max_tokens` cap bound the spend. A public deployment needs an access gate in front of it.
- Opus 5.5 always thinks; the backend never sends a `thinking` field and replays assistant turns unedited. Long conversations start a fresh model thread at 80 messages instead of trimming old turns. The Mon's state lives on the MCP server, so nothing is lost.
- The scripted mock model (`SIM_MODEL_BACKEND=mock`) exists for tests and offline runs. It calls the same status tool whatever the user says, and the UI labels it "Scripted test model". It is not a router and must not appear in the demo video.
