# NVIDIA / Nebius runtime adapter

Implementation begun 2026-10-24. This adapter is NOT live-runtime evidence.

`packages/web-sim/server/nebius.ts` implements the existing simulator's `ModelBackend` interface using native server-side fetch. It preserves the existing MCP tool loop rather than introducing another agent framework. It accepts only reviewed NVIDIA model IDs and official Nebius HTTPS endpoints, refuses redirects, caps response sizes, propagates cancellation, validates responses with Zod, rejects invented tools and emits metadata-only receipts. No fallback to Bedrock or a mock is implemented.

Initial transport is a buffered chat completion followed by the existing simulator SSE message protocol. It is not token-by-token Nebius streaming. Existing model-auth and rate-limit checks must remain in front of this backend when the simulator wiring lands. Unsupported image/thinking history fails closed; start a fresh conversation when switching providers.

## Qualification gates

- [ ] Adapter selected in the existing simulator and correctly labelled.
- [ ] `NEBIUS_API_KEY` configured in the server/secret manager, never the browser or source.
- [ ] Exact selected model exists in the account's current `/models` response.
- [ ] Actual inference and an actual model-selected care tool succeed through Nebius.
- [ ] Receipt and source commit recorded without prompts, user memory, tokens, or credentials.
- [ ] Real database mutation and a new-session continuity check pass.

Offline unit tests use an injected transport and never count toward these live gates. A receipt generated by an injected test transport is a test fixture, not provider proof.

## Verified API seams

Installed `@anthropic-ai/sdk` 0.135.0 Message, Usage, TextBlock and ToolUseBlock definitions were read before implementing the existing protocol adapter. Zod 4.6.7, TypeScript ~6.0.3, Vitest 5.0.5 are the repository's pinned versions. No dependency upgrade is required.
