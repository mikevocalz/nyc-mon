# M07 Caller name: accessibility

Owner: `a11y-auditor`. Standard: WCAG 2.2 AA (https://www.w3.org/TR/WCAG22/), Apple HIG and Android accessibility. Inputs: `03-direction.md`, `04-components.md`, `05-copy.md`, `06-critique.md`, `docs/design/DECISIONS.md` (P4, D10), `docs/DESIGN_SYSTEM.md`, `docs/COPY_DECK.md`, kit source.

**Verdict:** likely accessible foundation after the shared kit fixes. The live plate must not chatter in a screen reader, and validation timing must give typists room before speaking.

## Focus order

1. Back (`m07.back.a11y.label`)
2. Title `m07.title`, `Heading level={1}`
3. Status row item, if consent is pending (`m05.badge.pending.a11y`), read before the field because it changes the hint's meaning
4. Caller name field (`m07.field.label`), with the hint read as its hint
5. Clear name (only when the field has text)
6. Error, when present (read as part of the field's description too)
7. Plate (`m07.plate.a11y.label`), only when the field has text
8. Use this name (`m07.continue`)

Initial focus: the title. The keyboard does not open automatically on native; a screen-reader user hears the question before the field (autofocus that raises the keyboard hides half the screen on SE and skips the title for VoiceOver). On web, focus also starts on the `h1`.

On Continue with a valid name: polite `m07.confirmed.a11y.announce`, then M08 owns focus.

## Screen reader labels and hints

| Element | Role | Label | Hint / state | Notes |
|---|---|---|---|---|
| Field | text field | `m07.field.label` | `m07.field.hint` (13+), `m07.field.hint.under13`, or `m07.field.hint.pending` | `textContentType="nickname"`, `autoCorrect={false}`, `autoComplete="nickname"`; `maxLength={16}` |
| Clear | button | `m07.field.clear.a11y.label` | — | Clearing returns focus to the field |
| Plate | text | `m07.plate.a11y.label` with the full name | — | Not a live region. It updates silently; a user who wants the preview moves to it. Not rendered when empty |
| Error | alert | `m07.error.blank` / `.too_long` / `.characters` / `.blocked` | — | Polite after the typing pause; assertive on Continue |
| Continue | button | `m07.continue` | when disabled: `m07.continue.a11y.hint.disabled` | Disabled is exposed as `accessibilityState={{ disabled: true }}`, still focusable so the hint is heard |
| Confirmed | announcement | `m07.confirmed.a11y.announce` | — | Polite |

Validation timing (2.2.1, 3.3.1): the error appears after a pause of at least 1 s with no keystroke, never per keystroke, so a slow typist or a switch user is not interrupted mid-word. `m07.error.blocked` never uses "offensive", "inappropriate" or "not allowed" (`05-copy.md`).

Pronunciation: names in any script are allowed. The plate's accessible label passes the name through unchanged; do not add `accessibilityLanguage` guesses.

## Dynamic Type

| Size | Behaviour |
|---|---|
| Default | plate at `type-station` (34 pt) holds about 13 characters on SE, steps to `type-title` (24 pt) up to 16 |
| XXL | plate text scales with Dynamic Type but is capped at the size where 16 characters fit on two lines; it wraps to two lines before it truncates |

## Findings

| # | Issue | WCAG | Severity | Fix |
|---|---|---|---|---|
| 1 | Error text 3.25:1 on daylit (kit) | 1.4.3 | Blocker | `danger` token |
| 2 | A live-region plate would speak every keystroke | 4.1.3 (noise) | High | plate is not live; error is the only announced update |
| 3 | Per-keystroke validation interrupts typists | 3.3.1, 2.2.1 spirit | High | ≥ 1 s pause before showing an error |
| 4 | Plate band vanishes on a night page | 1.4.11 (not required; legibility) | Low | 1 pt `silver` keyline at night |
| 5 | Autofocus would skip the title and cover SE with the keyboard | 2.4.3 | Medium | no native autofocus |
| 6 | Disabled Continue must stay focusable to explain itself | 4.1.2 | Medium | disabled state + `m07.continue.a11y.hint.disabled` |
