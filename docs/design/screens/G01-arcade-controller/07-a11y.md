# G01 Arcade controller overlay: accessibility

Owner: `a11y-auditor`. Standard: WCAG 2.2 AA (https://www.w3.org/TR/WCAG22/), Apple HIG accessibility (https://developer.apple.com/design/human-interface-guidelines/accessibility), Android accessibility (https://developer.android.com/guide/topics/ui/accessibility), Xbox Accessibility Guidelines for remapping and input (https://learn.microsoft.com/en-us/gaming/accessibility/guidelines), Rive semantics (https://rive.app/docs/editor/accessibility/semantics). Inputs: `03-direction.md`, `04-components.md`, `05-copy.md`, `06-critique.md`, `docs/design/research/arcade-ergonomics.md`, `docs/design/CONTRAST.md`, `packages/ui/game-controls/contract.ts`. Stage: design. Nothing is built; every row is a requirement, not a test result. Nothing has been verified on a device.

**Verdict:** likely accessible foundation. Three pairs are computed and not yet in the registry (Law 10 blocker), the Rive semantics tree is a runtime claim until a `--semantics` run shows it, and the floating-stick hit rule needs a device test.

## Contrast

Method: WCAG 2.2 relative luminance with the 0.04045 linearisation threshold, the same formula as `packages/theme/contrast.ts` (`contrastRatio`). Rows marked **registry** are already measured in `docs/design/CONTRAST.md` or `docs/DESIGN_SYSTEM.md`. Rows marked **computed** were calculated 2026-10-15 with that formula from the hexes in `packages/theme/tokens.ts` (`scratchpad/ratios.mjs`) and must be added to `packages/theme/contrast.ts` with their roles before the kit ships them (Law 10).

The controller is hardware and does not change with the scheme, so most pairs are `both`. The pill's keyline and the paused scrim touch the world, so they are measured against the two extremes of what the renderer can draw behind them, as `scrim-scene` is.

## Touch targets

Reference scale 1.0 from `arcade-ergonomics.md` §7–8; `ControllerProfile.scale` 0.8…1.4.

| Control | Size at 1.0 | At 0.8 | Min | Result |
|---|---|---|---|---|
| Cap ×6 | Ø56 dp | Ø44.8 | 44 pt iOS / 48 dp Android | pass iOS at every scale; Android passes at scale ≥ 0.86: the resolver clamps the Android floor to 0.86 (`08-handoff.md`) |
| Cap spacing (2.5.8) | 8 dp edge to edge along a row, 6 dp between Y and B | 6.4 / 4.8 | targets over 24 dp need no spacing | pass |
| Stick housing | Ø128 dp | Ø102 | 44 / 48 | pass |
| Stick thumbpad (the drag handle) | Ø56 | Ø44.8 | 44 / 48 | pass; the whole housing accepts the touch-down, so the pad's size is not the target |
| Pill | 120 × 44 dp | 96 × 35 | 44 / 48 | fails under 1.0: the pill does not scale below 1.0 (Decision below) |
| Hold-to-stop | same as the pill, held 1000 ms (`STOP_HOLD_MS`) | — | 2.5.1 pointer gestures: a path-free single-pointer hold | pass; cancel by release (2.5.2 pointer cancellation) |

**Decision: BUILD.** `scale` applies to the stick and the cluster; the pill stays 120 × 44 at every scale and grows to 144 × 48 on Android. A 35 dp pill at 0.8 would fail both floors.

**Dragging (2.5.7).** The stick is a drag. The non-drag path is the one `GameScreen.tsx` already has: the accessibility actions zoomIn … reset (`A11Y_ACTIONS`), reachable on the stick itself (`accessibilityActions`) and on web as keyboard arrows. Floating placement adds no drag that the fixed stick lacks.

## Focus order

The overlay is reachable from the world view. Order, left to right then top to bottom in the thumb groups, with the pill first because it is the control a screen-reader user most needs to find:

1. Pill (`StartStopPill`): role `button`, name per `pill/state`, hint per `05-copy.md`. Hold-to-stop is exposed as a custom accessibility action "Stop" (`g01.pill.stop_confirm` name) that performs the full hold without a timer, after a confirm alert; a focus-driven stop never happens by accident because the action is explicit (Xbox guideline 102: controls operable without timed input).
2. Stick (`AnalogStick`): role `adjustable`, name "Move", value the compass word, actions = `A11Y_ACTIONS` plus `moveBack`, `moveLeft`, `moveRight` for the directions the stick owns.
3. Caps in reading order X, Y, Z, A, B, C (mirrored handedness keeps the same order: the labels do not move in the tree, only on screen). Role `button`, name = `ActionBinding` spoken label, state `disabled` or value "Held" / "Ready in n seconds".
4. The world view with its existing accessibility actions stays after the controller.

Focus never fires an action (§9). Activation is the platform's explicit activate (double tap / Enter / Space). A cap activated by accessibility sends `buttonDown` then `buttonUp` 80 ms later through `GameInputRouter` with `source: 'accessibility'`, so the session sees a real press and `heldButtons` never sticks.

Rive semantics (directive §8): every control artboard authors role, name binding, state and the custom action list above so that where the runtime exposes a tree (web first) it matches this table. Where the runtime does not, the React Native wrapper owns the tree and the Rive view is `accessible={false}`. Proof is a `rive <project> --semantics` run per state (lane B) and a VoiceOver pass (lane F).

## Reduced motion map

Gated once by the sim-core adapter (`useReducedMotion` from `@acme/ui`, as `GameScreen.tsx` already does), passed down as `reducedMotion` and bound to `a11y/reducedMotion`. The controller never reads the OS itself.

| Motion | Full | Reduced (authored sibling) |
|---|---|---|
| Cap press | 4 dp sink, scale 0.97, 120 ms | glyph white, rim brightens, 120 ms, no movement |
| Cap release | 160 ms spring, one 2 dp overshoot | cuts to idle |
| Cap held | static ring | same |
| Cap cooldown | sweep around the well | "wait" chip, no sweep |
| Stick deflection | pad follows, 0–8° tilt, rings by radius | pad follows (the reading must stay visible), no tilt, rings by radius |
| Stick release | 200 ms spring, 4 dp overshoot | one-frame return |
| Pill press | 2 dp sink | colour only |
| Pill legend change | 120 ms cross-fade | cut |
| Hold-to-stop ring | continuous fill over 1000 ms, driven by `pill/holdProgress`; unwinds in 200 ms on release | four 250 ms steps; resets on release |
| Paused scrim | 200 ms fade | cut |
| START perimeter pulse | struck (`06-critique.md`) | — |
| Overlay mount | `motion-enter` full | `motion-enter` reduced (200 ms fade, no rise) |

Copy does not change in either mode (`05-copy.md`). Announcements fire at the same moments.

**Flash safety (2.3.1).** Nothing on the overlay blinks. The hold ring is one fill; the cooldown sweep is one revolution per cooldown; the held ring is static. The reduced hold ring's four steps are four luminance changes in 1000 ms, under the three-per-second limit only because they are not alternating (a step up is not a flash pair); keep them monotonic.

**Animation from interactions (2.3.3).** Every motion above is a response to the Caller's own press or the session's state change; none is decorative, and each has a reduced sibling.

## Dynamic Type

Cap letters and the pill legend are sized by `scale`, not by font scale: the caps are fixed-geometry hardware and must not grow past their wells. At the largest accessibility size the accessible name carries the meaning (the letter is hidden from the tree anyway). The "Hold to stop" caption (`type-caption`, 13 pt) does scale with Dynamic Type up to XXL and wraps to two lines under the pill; the resolver reserves 2 × 18 pt for it.

Large Content Viewer (iOS): each cap sets `accessibilityShowsLargeContentViewer` with its spoken action name, as the H-Lynk keys do.

## Input and timing

- 2.2.1 Timing adjustable: the only timed input is the 1000 ms hold (`STOP_HOLD_MS`), which is a deliberate safety delay for a destructive action and is replaced by the explicit "Stop" accessibility action; no gameplay here depends on time (the camera is static).
- 2.1.1 Keyboard (web and hardware keyboards): arrows move, Z/X/C/A/S/D or the gamepad adapter press caps, Space or Enter on the focused pill starts/pauses/resumes, and Stop is the same key held 1000 ms (`STOP_HOLD_MS`) or the "Stop" action from the context menu. Mapping lives in lane C's keyboard adapter and must dispatch the same `GameInputRouter` calls.
- 2.5.2 Pointer cancellation: a cap's action fires on up, never on down? No: a game button fires on down (`buttonDown`) by contract. The cancellation guarantee is the strict pairing: a touch that leaves the cap sends `buttonUp`, and `cancelAll` on interruption. This is a documented exception to up-event activation, allowed by 2.5.2 where "completing the function on the down-event is essential".
- 2.5.5 Target size enhanced (AAA) is met at scale ≥ 0.8 on iOS.

## Responsive and foldable

Profiles from `LayoutProfile`; hinge rules from the mikevocalz-foldable-layouts skill via `packages/app/features/game/hud-layout.ts` (`usableRegions` cuts by every separating or fully occluding fold).

| Profile / posture | Behaviour |
|---|---|
| phone-portrait | Stick lower-left, cluster lower-right, pill in the upper safe band; the camera's key region (centre third) stays clear |
| phone-landscape | Both groups in the lower grip zones, the pill top-centre 12 dp below the inset, nothing under the system edge gestures (16 dp margin from every edge) |
| fold-outer | phone-portrait at the outer panel's width |
| fold-book (vertical hinge) | Stick wholly in the left region, cluster wholly in the right; the pill in whichever region is wider, never across the hinge; input survives fold/unfold via `cancelAll('fold-change')` then remount |
| fold-tabletop (horizontal hinge) | World in the upper region; the stick, cluster and pill all in the lower region, the pill centred on that region's upper edge; nothing crosses the hinge; the session is not reset |
| tablet | Clusters near the real grip corners; position and size adjustable (G03); `scale` default 1.2 |
| web | Pointer and keyboard; multitouch where supported; no full Game screen on web today (`GameScreen.tsx` header), so this profile is for the shared layout contract and Storybook |

## Findings

| # | Issue | WCAG | Severity | Fix |
|---|---|---|---|---|
| 1 | Three pairs (`royal-400` on `concrete-900` / `concrete-800`, `carolina-500` on `signage-black`) are computed, not registered | Law 10 (repo) | High (blocks kit) | Theme owner adds rows and the `royal-500` on `concrete-900` forbidden rule |
| 2 | A cap fires on the down event | 2.5.2 | Medium (documented exception) | Strict down/up pairing and `cancelAll`; state the exception in the component JSDoc |
| 3 | The pill at `scale` < 1.0 would fall under 44 pt | 2.5.8 | High | Pill ignores `scale` (Decision above) |
| 4 | Android 48 dp floor fails at scale < 0.86 | Android target floor | Medium | `ControllerLayoutResolver` clamps the Android minimum scale to 0.86 |
| 5 | Floating stick can claim a touch meant for a cap | 2.5.1, usability | Medium | Floating mode ignores touch-downs inside any cap's hit circle + 8 dp |
| 6 | Rive semantics tree on native is unproven | 4.1.2 | Medium | Wrapper owns the tree until a `--semantics` run and a VoiceOver pass show the Rive tree matches this table |
| 7 | Announcements during fast play could stack | 4.1.3 | Low | Only `cancelAll` and pill state changes announce; cap presses never do |

## Device checks (open, no device yet)

From `docs/DEVICE_CHECKS.md` conventions, added for this screen: VoiceOver and TalkBack walk the order above and the "Stop" action asks before stopping; two caps held while the stick moves on iPhone SE 3, 16 Pro Max and Pixel 8 (multitouch); fold/unfold on a Pixel Fold and a Galaxy Z Fold while A is held (`cancelAll('fold-change')` fires, no stuck cap); tabletop posture puts nothing on the hinge; reduced motion on: no sink, no spring, stick reading still visible; press-to-sink latency under one frame at 60 and 120 Hz; real-gamma contrast of `royal-400` on graphite under a daylit city.
