# Ops console: accessibility

Owner: `design-director`. Written 2026-10-04. Standard: WCAG 2.2 AA (https://www.w3.org/TR/WCAG22/). Applies to `03-direction.md` and the components in `04-components.md`. Staff use this tool for hours, mostly with a keyboard on a laptop *(assumption)*, so keyboard paths get the most detail.

## Structure and landmarks

Every screen, from `@acme/ui/html` only:

```
Page
├─ (SignageBand strip, when integrity fails: role="alert" on first appearance)
├─ Nav "Console"                     sidebar, or TabBar in navigation mode
└─ Main
   ├─ Section "Callers" (list pane)  aria-labelledby → the h1
   │  ├─ Search                      SearchBar + FilterBar
   │  └─ Table + TableCaption        DataTable
   ├─ Section (detail pane)          aria-labelledby → the record's h2
   └─ Aside "History" (inspector)    when rendered
```

- One `h1` per screen (`Heading level={1}`), in the list pane on list screens and the detail pane on two-pane screens. The record name in the detail is `h2`; its sections are `h3`. No skipped levels.
- The skip link "Skip to main content" is the first focusable element, visible on focus.
- Page title per route: "{Record or section} · NYC-MON console", updated on navigation (WCAG 2.4.2). Route changes move focus to the new `h1` or the record's `h2` and announce it through the title change.

## Keyboard

### Global

| Key | Does |
|---|---|
| Tab / Shift+Tab | moves through: skip link, nav, list pane controls, table, detail, inspector toggle |
| Escape | closes the open dialog, sheet, menu or inspector; returns focus to the control that opened it |
| Enter / Space | activates links and buttons |

### Tables (`DataTable`, G2)

The table is a real `<table>`, not an ARIA grid. Each row's primary cell holds the row link, so a table of 50 rows is 50 tab stops plus header buttons. That is acceptable at 50 rows per page and keeps the screen-reader table model intact; a roving-tabindex grid is DEFERRED until a list needs more than 50 rows per page.

| Element | Tab | Enter / Space | Notes |
|---|---|---|---|
| Sortable header | yes | toggles sort (asc → desc → none) | `Button` inside `TableHeaderCell`; `aria-sort` on the cell; label `admin.a11y.sort` |
| Row link (priority-1 cell) | yes | opens the record in the detail pane; on `compact` pushes the detail | selected row gets `aria-current="true"` |
| Row disclosure (dropped columns) | yes | expands the row in place | `aria-expanded`, `aria-controls` |
| Row checkbox (bulk lists only) | yes | toggles | `Checkbox` labelled with the row's priority-1 value |
| Pagination | yes | | `Nav aria-label="Pagination"`, status `admin.a11y.page_status` as polite live text |

After opening a record from the list on `medium` and up, focus moves to the detail's `h2`. Shift+Tab from there goes back into the list at the selected row (focus order follows DOM order: list pane before detail pane).

### Record rows layout

The header row stays in the DOM, visually hidden (`VisuallyHidden`, H5). Each record row is still one `TableRow`; its two lines are cells. Screen readers announce column names; sighted users see a list.

### Dialogs and sheets (`ResponsiveDialog`, G9)

- Focus moves to the dialog's first field (the reason `Select`), not the destructive button.
- Focus is trapped inside; Escape closes and returns focus to the trigger. Kit `Dialog` already traps focus and closes on Escape (`packages/ui/Dialog.tsx` lines 232–259). `BottomSheet` needs `aria-modal="true"` (G9).
- The destructive button is disabled until the confirm text matches; its disabled state is announced (`aria-disabled` with a hint "Type the code to enable").

### Masked values (G6)

- "Show" is a button with the field in its name: "Show email. Asks for a reason." (`admin.mask.show.a11y`).
- After a reveal, focus moves to the revealed value's "Hide" button, and the value is announced once through a polite live region.

### Inspector

- The "Show history" toggle is a button with `aria-expanded`. Opening moves focus to the inspector heading; Escape closes it.

### Forbidden in the console

- `orange-500` as text or icon on daylit (2.38:1 on `concrete-50`; existing forbidden row).
- Opacity modifiers on text (`text-text-muted/50`); `CONTRAST.md` findings 1–2 came from exactly that.
- White on `apple-500` (4.21:1); use `apple-600` faces.

## Targets and pointer

- Every interactive element is at least 44 × 44 CSS px at every width, including table header sort buttons, chip remove buttons, copy buttons and pagination (WCAG 2.5.8 needs 24; the console holds 44 because staff use touch laptops and tablets).
- Record rows are 56 px minimum; the whole row is the link.
- Nothing requires a drag. Resizable panes (if the split view's divider is enabled) also have a keyboard path: the divider is a `Button` with Left/Right arrow steps, or is disabled in the console.

## Reflow, zoom and text spacing

- At 320 CSS px wide (WCAG 1.4.10; 1280 at 400% zoom) the `compact` layout holds with no two-dimensional scroll: record rows, stacked key/value pairs, sheets.
- At 200% text zoom, record rows grow in height; badges wrap under the name instead of truncating it.
- Ids truncate in the middle with the full id in the accessible name and the copy button; names never truncate below 2 lines.

## Foldables

- No interactive element, table, form or dialog straddles a hinge (`03-direction.md`, "Foldables"). A dialog on a tabletop fold opens wholly in the bottom segment; focus order still runs top segment then bottom.
- Changing posture keeps focus on the same element; if that element moves to another segment, it stays focused and is scrolled into view.

## Motion

- Pane transitions use `motion-step` (200 ms slide) with the authored reduced sibling (120 ms cross-fade), per `docs/DESIGN_SYSTEM.md`.
- The inspector drawer slides in 200 ms; reduced motion shows it with a 120 ms fade.
- The integrity band does not animate between states; the colour change and the live text are the signal.
