# v3 Harlem tile — F1 device verification, Surface Duo, 2026-10-17

Lane `lane-v3e3` @ `23ec560` (E1 decoder + E2 bake + E3 renderer consumption on
main `2376a30`). Every number below came from one release build on the physical
bench Surface Duo (adb serial `913949703467`, Android 14 GSI, SDK 34, 2700×1800
@ 60.000004 Hz — device record in `docs/DEVICE_CHECKS.md`). Method mirrors the
M0 baseline (`baseline-duo-2026-10-17.md`); nothing here is from a dev client,
simulator or estimate.

## Build under test

- `apps/mobile` release APK `app-mobile-release.apk`, **137,978,841 bytes**
  (M0 v2 build: 140,402,822).
- Hermes bundle `index.android.bundle`, **15,707,936 bytes** (M0: 15,480,356 —
  +227,580, consistent with the bundled tile growing 1,009,994 → 1,238,200
  bytes). Bundle contains `harlem-apollo-20261017` and the `[NYC-Mon/perf]`
  probe markers — the APK carries the v3 tile, verified by grepping the bundle
  extracted from the APK.
- `./gradlew :app:assembleMobileRelease` — BUILD SUCCESSFUL in 22 m 21 s (first
  build in this worktree; M0's was a rebuild). `EXPO_PUBLIC_GAME_PERF=1` via
  `apps/mobile/.env` (`env: export EXPO_PUBLIC_GAME_PERF` in the `export:embed`
  log; gitignored). The probe defaults off, cost is one `console.info` per
  120 frames.
- Worktree caveat reused from M0: `apps/mobile/node_modules` and
  `packages/*/node_modules` must resolve `@acme/*` into this worktree, not the
  main checkout. This worktree shipped `apps/mobile/node_modules` as a symlink
  to `nyc-mon`'s (which would have silently bundled `main`); it was replaced
  with a real directory mirroring main's links plus `packages/spatial`,
  `mcp-server`, `payload`, `web-sim` (missing). Verified post-build:
  `@acme/app` realpaths to `/Users/mikevocalz/nyc-mon-v3e3/packages/app` and the
  bundle contains the v3 dataset id.

## Run under test

Onboarding is still broken in release builds (M0 caveat: `startIncubation`
throws on release Hermes); the run bypassed it via the `nycmon://game` deep
link, same as M0. Three cold starts, then a scripted drive:

- Cold start → deep link → lobby → START → city loaded → analog stick held:
  ~35 s north, then ~50 s east (M0 pattern; `argent gesture-custom`, Down at
  the stick centre, Move to full deflection, 1 s Move keeps, Up at the end;
  87 events over ~84 s). Stick state confirmed on the accessibility tree
  mid-hold (`Move, Analog stick, North`).
- `dumpsys gfxinfo … reset` at 19:03:02 (≈6 s after the city was ready,
  paused canvas idle), drive 19:03:05–19:04:29, dumps at ~19:04:34. The
  window is ~3 s settle + ~84 s walking + ~5 s after release.

## Reading

- The v3 tile runs on hardware at the same cadence as v2: p50 frame time is
  identical (36 ms ≈ ~28 fps effective under vsync pacing). The p90–p99 tail is
  ~4–5 ms *better* than M0's, while the janky share is higher (44 % vs 34 %) —
  that metric is window-sensitive: M0's window carried ~10 s of idle settle
  frames plus a longer run (145 s vs ~92 s here). Per-frame mass sits at
  28–46 ms either way.
- Triangles on device read ~310 k vs v2's host-counted ~286 k (+9 %) — the
  price of v3 detail fields (floors, storefronts, detail bits) driving more
  geometry. The draw-call comparison is not apples-to-apples: 40–41 here is the
  device `renderer.info` count from the N1 probe; M0's 26 was a host-side
  scene-graph floor. N9's "draw calls equal to v2" is asserted in the node
  test, not measured twice on this device.
- Scene build (~1.6 s worst frame) and memory (+20–29 MB at scene start) grew
  with the 1.24 MB tile, but the first-load path (parse + build + Dawn
  `compileAsync`) still lands in the same ≤15 s cold / ~6.5 s warm envelope.

## Verified / not verified

- **Verified:** v3 dataset in the shipping bundle (`harlem-apollo-20261017`);
  scene builds and renders on the Duo (accessibility "3D map of Harlem, around
  the Apollo Theater" + non-blank frames in `city-*.png`, `walk-end.png`);
  84 s of real walking input (stick state observed `North` mid-hold);
  no crashes; frame/memory numbers above.
- **PENDING:** per-phase parse-ms and build-ms on device — the probe reports a
  single 1,617 ms worst frame containing them but does not split them; a
  finer-grained marker would need a probe change (out of scope for this lane).
- **PENDING:** landmark identification in frames (Apollo marquee on the

  F3's critique pass owns visual identification.
- **PENDING:** second-device numbers (D2 names an iPhone SE 3 class device) —
  the Duo is the only bench device; not measured.
- **Not repeated:** the perfetto trace and GPU timestamp work from M0; the
  gfxinfo GPU histogram shows the same capped 4 950 ms tail bucket.
